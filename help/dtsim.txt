dtsim — simulation runner (full reference: docs/dtsim/README.md)

Entry
  autowire dtsim <cmd>       ln -s autowire.js dtsim (or out/autowire) → ./dtsim <cmd>
  dev: bun index.ts dtsim <cmd>
  Config is selected by [dtsim] config in autowire.toml, default
  <project>/dt/config/dtsim.config.ts. No --config flag.

Layout
  <project>/                 RTL design dir; filelists and ${workspace} resolve here
  <project>/dt/              testbench code
  <project>/dt/config/       dtsim.config.ts and case modules (TypeScript SoT), file.lst
  <project>/dt/config/.dtsim/dsl/   DSL copy, rewritten on every run (generated)
  <project>/dt/simout/       outputs (generated, git-ignored); with several tools
                             one tree per tool: dt/simout/<tool>/...
    <case>/                  run: compile dir (run_compile, compile log, error.txt)
    <case>/<seed>/           run_sim, sim.log, .result → STATUS, error.txt, grade.log
    regression/              regr ([<label>/]regression with -d): compile_<build>/,
                             <case>/<seed>/, regression.txt (plan), result.txt,
                             dresults (forwards to dtsim results)
Commands
  run <case>                 compile + simulate one case (--compile-only, --sim-only,
                             --interactive); case ids are dotted (base.sub.sub)
  regr [group]               regression (default *): shared compiles per build
  plan [group]               the regression plan tree, no run
  list [case]                case trees (default 2 levels; -L <n>, --all; a case scopes)
  groups                     regression groups
  env --case <id>            the environment a case would get (--phase, --show-values)
  results --dir <dir>        statuses under a dir (--recheck re-grades, --csv)
  common flags: -d <label>, -v (logs: above the live panel on a TTY), --plain
  The config is selected by [dtsim] config in autowire.toml (default
  dt/config/dtsim.config.ts). Config EnvVarDoc.flags are registered as real
  Commander options before parsing; seed knobs are config-owned.

Tools, wave and coverage (config-owned)
  Tool selection: no --tool / $DTSIM_TOOL. Each tool has a probe (executables on
  PATH: vcs, verilator); dtsim auto-fallbacks to the first available, in tools
  order. A config factory can order/filter tools to force one.
  Wave / coverage: no --wave / --cov flags. The config sets DTSIM_WAVE /
  DTSIM_COV (and _DEPTH/_TOP/_METRICS/_MERGE) itself, typically in its factory;
  backends read them at compile/sim time. VCS writes dump.tcl and runs simv
  -ucli -i dump.tcl → <seed>/verilog.fsdb (and adds -debug_access+all unless
  set). Verilator: --trace-fst plus a bound dtsim_wave module → <seed>/wave.fst
  (needs top; a C++ harness calls traceEverOn(true)).

Agent workflow
  1. dtsim list / dtsim groups / dtsim plan <group>: see what exists, no run.
  2. Change behavior only in dt/config/*.ts (cases, groups, grader, tool,
     launcher, hooks). Never edit dt/simout/ or dt/config/.dtsim/.
  3. dtsim run <case> --plain: one line per step; exit 0 = PASS / PASS WITH ERRORS.
  4. On a failure read <dir>/error.txt first (status, phase, grader rows,
     excerpt), then the log it names. Rerun by hand: <case>/run_compile,
     <case>/<seed>/run_sim [-s seed].
  5. dtsim regr <group> --plain; the stdout ends with a results tree and a
     Summary table; `results --dir dt/simout/regression` re-reads it later.
  Statuses: PASS, PASS WITH ERRORS, FAIL, NO SIM LOG, ABORTED (from sim.log
  via the grader, never the exit code).

DSL (import from ./.dtsim/dsl/index.ts)
  Workspace(regEnv, opts | ((mode:"run"|"regr") => opts)); or Workspace({...}).
            regEnv: registered env vars [{name, values?, default?, desc?, flags?, set?}],
            listed by `dtsim env`; flags are Commander option specs registered
            before parsing. `set(value)` maps the parsed value to the env var.
            The factory computes the opts from the mode:
            read env, default DTSIM_WAVE, choose tools, set slots and seeds.
  tools     [VcsTool({ top, ntbOpts, flags, command, casePlusarg })
            | VerilatorTool({ top, mdir, main, command })
            | defineTool({ name, passthrough, compile, simulate, ... }), ...];
            top default: tb_top. casePlusarg (default "TEST")
            sends +TEST=<case>; false sends none. Case toolOptions cannot override top.
  filelists dtsim never reads them: each is -f <abs path>, compiled with the
            project root as cwd (relative entries, nested -f, -F, $VAR are the
            simulator's); case filelists append to the workspace's.
  bareDefaults  base of every top-level case; derived cases inherit it.
  task      { launcher, maxSlots, maxCompiles }; launcher LocalLauncher() (default)
            | LsfLauncher({ queue, args }) | SlurmLauncher(...) | defineLauncher(...)
            | a probe list [Lsf, Slurm, Local] tried in order, first on PATH wins
            (probed concurrently). DTSIM_TASK_TYPE=local|lsf|slurm forces one;
            DTSIM_TASK_QUEUE sets the queue. Cluster launchers also write
            bjob_*/srun_* submit wrappers beside run_sim/run_compile/run_verdi.
            maxSlots/maxCompiles: a number, or (ctx:{tool,launcher})=>number,
            evaluated after tool+launcher resolve (no manual probe needed).
  vcsBaseFlags({ timescale?, jobs?, debugaccess?, add? }) → [-full64, -sverilog,
            ...] (SV and -full64 always on; debugaccess "all"|"pp"|"r"|"w"|"f"|
            "drivers" optional). verilatorBaseFlags({ jobs?, timing?, timescale?,
            add? }) → [--sv, ...]. Spread and extend for a tool's flags or a
            case's compileArgs.
  Case(name, opts); c.SubCase(suffix, opts | (parent) => opts) → <id>.<suffix>;
            export top-level cases (alone or in an exported array / Set / Map).
            opts: defines, compileArgs, simArgs, env
            ({ value, scope: "sim" } keeps it out of the build), uvm, toolOptions,
            filelists, grader, random, owner, abstract (base used only for
            derivation; never run, left out of * and <base>.* hits), tools:
            ["verilator"] (runs only there; regr / plan skip it elsewhere),
            byTool: { vcs: {...} } (merged on top when that tool is selected).
            Lists append, maps merge.
  Group(name, [caseObj, "id", "base", "base.*", "base.**"]); no reserved "all"
            group — the group arg may be a pattern: * = top-level cases (the old
            all), ** = every depth. An abstract base expands to its leaves.
  grader    DefaultGrader({ pass, error, expect, waive: [WaiveRule(n, p)], uvm })
            (default; UVM report check on), g.extend({...}) appends; custom
            defineGrader({ name, grade(ctx) }) → Status | { status, note,
            details, highlight }; scanLog / streamLines read big logs in a worker
  hooks     { preCompile, postCompile, preSim, postSim, onResult }: (ctx) => ...
            or a list; ctx.sh(cmd) runs bash with the phase env; a throw fails
  Placeholders ${workspace} ${verify} ${output_dir} ${case} ${seed} ${tool};
  paths also take shell vars (${HOME}); unknown names fail.
  Children get only passthrough-listed env vars (tool + launcher + env.passthrough).

Output
  stdout: Run / Regression / Summary tables, plan tree, results tree; all tables
  (incl. groups / env / results) fit the terminal width, a pipe/file uses 100.
  stderr: progress. TTY: spinner panel ([spinner] [elapsed] [phase] <log> <size>,
  "-" until a log is on disk), the submitted command between two full-width
  rules titled cmd (no side borders, so it copies cleanly). regr:
  live build trees, then a bar line. Bar: each build 1/N, each of its k sims
  1/(N·k); compile layer built blue █, build failed grey █, building ░, waiting
  grey ░; finished sims cover it from the left: PASS green █, PASS WITH ERRORS
  yellow █, other red █. Status OK (a compile) is blue, PASS green.
  No TTY / --plain: concise start / end lines only.
