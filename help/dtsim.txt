dtsim — simulation runner (full reference: docs/dtsim/README.md)

Entry
  autowire dtsim <cmd>       ln -s autowire.js dtsim (or out/autowire) → ./dtsim <cmd>
  dev: bun index.ts dtsim <cmd>
  Config: [dtsim] config in autowire.toml when set (or when the default
  dt/config/dtsim.config.ts there exists), else searched upward from CWD;
  it must live in <project>/dt/config/. No --config flag. --help / help /
  --version / results --dir (no --recheck) work without a config.

Layout
  <project>/                 RTL design dir; filelists and ${workspace} resolve here
  <project>/dt/              testbench code
  <project>/dt/config/       dtsim.config.ts and case modules (TypeScript SoT), file.lst
  <project>/dt/config/.dtsim/dsl/   DSL copy, rewritten on every run (generated)
  <project>/dt/simout/       outputs (generated, git-ignored); with several tools
                             one tree per tool: dt/simout/<tool>/...
    <case>/                  run: compile dir (run_compile, compile log, error.txt)
    <case>/<seed>/           run_sim, sim.log, .result → STATUS, error.txt, grade.log
    regression/              regr ([<label>/]regression with -d): compile_<build>/,
                             <case>/<seed>/, regression.txt (plan), result.txt,
                             dresults (forwards to dtsim results)
Commands
  run <case>                 compile + simulate one case (--compile-only, --sim-only,
                             --interactive); case ids are dotted (base.sub.sub)
  regr [group]               regression (default *): shared compiles per build
  plan [group]               the regression plan tree, no run
  list [case]                case trees (default 2 levels; -L <n>, --all; a case scopes)
  groups                     regression groups
  env --case <id>            the environment a case would get (--phase, --show-values)
  results --dir <dir>        statuses under a dir (--recheck re-grades, --csv)
  common flags: -d <label>, -v (logs: above the live panel on a TTY), --plain
  Config EnvVarDoc.flags become real options of run / regr / plan / list /
  groups / env; seed knobs are config-owned.

Tools, top, wave and coverage (config-owned)
  Tool selection: each tool has a probe (executables on PATH: vcs, verilator);
  dtsim picks the first available in tools order. A config factory orders or
  filters tools to force one.
  top (default "tb_top"), wave (default false), waveDepth (0 = all levels),
  waveScope (default: the case's top) are Workspace defaults; a case sets its
  own, derived cases inherit it. top, and with wave on also depth/scope, are in
  the compile key. A --wave flag is a config's registered WAVE option.
  Wave files are <case id>.fsdb (VCS) / <case id>.fst (Verilator) in each seed
  dir. run_verdi uses ${output_dir}/${DTSIM_CASE}.fsdb; bsub_verdi/srun_verdi end
  in & to return immediately (compile/sim wrappers still wait).
  cov (default false) and covMetrics (VCS -cm syntax, default
  line+cond+fsm+tgl+branch+assert) work like wave: Workspace defaults, case
  override, in the compile key when on. Only backends with `coverage` collect
  it (VCS); Verilator ignores cov. dtsim never merges: VCS writes per build
  run_cov_merge (urg -> merge.vdb, urgReport) + run_verdi_cov (merge.vdb once
  merged, else simv.vdb), and per regression run_cov_merge_all +
  run_verdi_cov_all (opens the merged-all merge.vdb); cluster launchers add
  bsub_/srun_ wrappers. At the end a Coverage list names databases and scripts.
  No DTSIM_COV* env vars; a --cov flag is a config's registered COV option.

Agent workflow
  1. dtsim list / dtsim groups / dtsim plan <group>: see what exists, no run.
  2. Change behavior only in dt/config/*.ts (cases, groups, grader, tool,
     launcher, hooks). Never edit dt/simout/ or dt/config/.dtsim/.
  3. dtsim run <case> --plain: one line per step; exit 0 = PASS / PASS WITH ERRORS.
  4. On a failure read <dir>/error.txt first (status, phase, grader rows,
     excerpt), then the log it names. Rerun by hand: <case>/run_compile,
     <case>/<seed>/run_sim [-s seed].
  5. dtsim regr <group> --plain; the stdout ends with a results tree and a
     Summary table; `results --dir dt/simout/regression` re-reads it later.
  Statuses: PASS, PASS WITH ERRORS, FAIL, NO SIM LOG, ABORTED (from sim.log
  via the grader, never the exit code). Each run starts compile.log / sim.log
  empty, so a rerun in the same dir is graded on its own output.

DSL (import from ./.dtsim/dsl/index.ts)
  Workspace(opts) or Workspace(regEnv, opts | ((mode:"run"|"regr") => opts)).
            regEnv: registered env vars [{name, values?, default?, desc?, flags?, set?}],
            listed by `dtsim env`; flags are Commander option specs, set
            before the factory runs (read them inside it). `set(value)` maps
            the parsed value to the env var.
            opts: tools, top, wave, waveDepth, waveScope, cov, covMetrics,
            filelists, output, seeds, grader, bareDefaults, env, task, hooks,
            groups, cases.
  tools     [VcsTool({ ntbOpts, flags, command, casePlusarg })
            | VerilatorTool({ mdir, main, command })
            | defineTool({ name, passthrough, compile, simulate, seedArg,
                coverage: { db, merge, mergeAll }, ... }), ...];
            casePlusarg (default "TEST") sends +TEST=<case>; false sends none.
            Case toolOptions override these per key.
  filelists dtsim never reads them: each is -f <abs path>. The compile runs in
            the compile dir (sims in their seed dirs), so relative entries
            resolve there: name sources $WORKSPACE/... (set to the project
            root; autowire analysis expands it too). Nested -f, -F, $VAR are
            the simulator's; case filelists append to the workspace's.
  bareDefaults  lowest-priority case options; every case inherits them.
  task      { launcher, maxSlots, maxCompiles }; launcher LocalLauncher() (default)
            | LsfLauncher({ queue, args }) | SlurmLauncher(...) | defineLauncher(...)
            | a probe list [Lsf, Slurm, Local] tried in order, first on PATH wins
            (probed concurrently). DTSIM_TASK_TYPE=local|lsf|slurm forces one;
            DTSIM_TASK_QUEUE sets the queue. Cluster launchers also write
            bsub_*/srun_* submit wrappers beside run_sim/run_compile/run_verdi.
            maxSlots/maxCompiles: a number, or (ctx:{tool,launcher})=>number,
            evaluated after tool+launcher resolve (no manual probe needed).
  vcsBaseFlags({ timescale?, jobs?, debugaccess?, kdb?, add? }) → [-full64, -sverilog,
            ...] (SV and -full64 always on; debugaccess "all"|"pp"|"r"|"w"|"f"|
            "drivers" optional). verilatorBaseFlags({ jobs?, timing?, timescale?,
            add? }) → [--sv, ...]. Spread and extend for a tool's flags or a
            case's compileArgs.
  Case(name, opts); c.SubCase(suffix, opts | (parent) => opts) → <id>.<suffix>;
            export top-level cases (alone or in an exported array / Set / Map).
            opts: defines, compileArgs, simArgs, env
            ({ value, scope: "sim" } keeps it out of the build), uvm, toolOptions,
            top, wave, waveDepth, waveScope, cov, covMetrics, filelists,
            grader, random, owner,
            abstract (base used only for
            derivation; never run, left out of * and <base>.* hits), tools:
            ["verilator"] (runs only there; regr / plan skip it elsewhere),
            byTool: { vcs: {...} } (merged on top when that tool is selected).
            Lists append, maps merge.
  Group(name, [caseObj, "id", "base", "base.*", "base.**"]); no reserved "all"
            group — the group arg may be a pattern: * = top-level cases (the old
            all), ** = every depth. An abstract base expands to its leaves.
  grader    DefaultGrader({ pass, error, expect, waive: [WaiveRule(n, p)], uvm })
            (default; UVM report check on), g.extend({...}) appends; custom
            defineGrader({ name, grade(ctx) }) → Status | { status, note,
            details, highlight }; scanLog / streamLines read big logs in a worker
  hooks     { preCompile, postCompile, preSim, postSim, onResult }: (ctx) => ...
            or a list; ctx.sh(cmd) runs bash with the phase env; a throw fails
  Placeholders ${workspace} ${verify} ${output_dir} ${case} ${seed} ${tool};
  paths also take shell vars (${HOME}); unknown names fail.
  Children get only passthrough-listed env vars (tool + launcher + env.passthrough).

Output
  stdout: Run / Regression / Summary tables, plan tree, results tree; all tables
  (incl. groups / env / results) fit the terminal width, a pipe/file uses 100.
  stderr: progress. TTY run: the last liveLines (Workspace, default 10; 0 = last
  line only) lines the compiler / simulator prints, between rules titled with
  the step, read from the child (a PTY on POSIX, pipes on Windows; colour and \r
  redraws removed), above [spinner] [hhh:mm:ss] [phase] <log> <size>. A failed
  compile / sim (or a sim whose grade fails) leaves them on screen. The submitted
  command shows between two full-width rules titled cmd. regr: live build
  trees, then `running nnn hhh:mm:ss [bar] compile xxx/NNN sim yyy/MMM` (fixed
  width; the bar fills the rest, text only below 10 cells; it stays after the
  run). Bar: each build 1/N, each of its k sims 1/(N·k); compile layer built
  blue █, build failed grey █, building ░, waiting grey ░; finished sims cover
  it from the left: PASS green █, PASS WITH ERRORS yellow █, other red █, each
  present status at least one cell. Status OK (a compile) is blue, PASS green.
  No TTY / --plain: concise start / end lines only.
